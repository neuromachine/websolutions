# Индекс Задач и Техдолга

В данном документе собран и структурирован весь текущий технический долг, открытые баги и намеченные улучшения для клиентской части приложения **websolutions**. Каждая задача снабжена приоритетом и кратким описанием.

---

## 🔴 Высокий приоритет (Критические задачи)

### 1. Переименование `section` → `scope` во всех файлах
* **Статус:** ⏳ В очереди
* **Описание:** Механическое переименование остаточных вхождений слова `section` в `scope` во всех файлах проекта. Это критически важно сделать до дальнейшего расширения кодовой базы, чтобы исключить путаницу в терминологии.
* **Затронутые области:** `uiStore.js`, конфигурационные файлы, роуты и компоненты отображения.

### 2. Поддержка объектов путей `{ name, params }` в компоненте `AppLink`
* **Статус:** ⏳ В очереди
* **Описание:** Текущая реализация `<AppLink>` поддерживает только строковые пути (`to="/portfolio"`). Необходимо добавить полную поддержку объектов путей (например, `:to="{ name: 'blocks_item', params: { slug: item.slug } }"`), чтобы сохранить преимущества именованных маршрутов Vue Router с автоматическим добавлением префикса `scope`.

---

## 🟡 Средний приоритет (Архитектурные доработки и API)

### 3. Защита от `null` в `buildPageVars` при неполных схемах
* **Статус:** ⏳ В очереди
* **Описание:** При использовании неполных схем загрузки в оркестраторе (например, только `'category'` без `'item'`), попытка обратиться к вложенным свойствам элемента (например, `item.slug`) может вызвать ошибку `TypeError: Cannot read properties of null`. Нужно внедрить защитные проверки (`?.` и дефолтные значения) внутри метода `buildPageVars` стора `uiStore`.

### 4. Scope-агностичные ссылки на стороне API
* **Статус:** ⏳ В очереди
* **Описание:** Совместно с бэкенд-разработчиками изменить эндпоинт `navigation`, чтобы ссылки возвращались в чистом виде (например, `/portfolio` вместо `/ru/portfolio`). Это позволит отказаться от временного костыля в виде утилиты `normalizeLink` на фронтенде.

### 5. Первые шаги к Server-Driven UI
* **Статус:** ⏳ В очереди
* **Описание:** Создать `pageStore`, реестр блоков `src/registry/blocks.js` и базовый компонент `PageRenderer.vue` согласно [Спецификации Server-Driven UI](sdui_spec.md).

### 6. Доработка вложенностей в `buildPageVars`
* **Статус:** ⏳ В очереди
* **Описание:** Проверить и доработать логику формирования заголовков и хлебных крошек для глубоко вложенных сущностей при схемах `structure+category+item`.

## 🟢 Низкий приоритет (Рефакторинг и Удобство)

### 7. Перенос `navigationStore.setLoading` из getters в actions
* **Статус:** ⏳ В очереди
* **Описание:** В `navigationStore` метод `setLoading` ошибочно или исторически находится в секции `getters`. Его нужно перенести в секцию `actions` для соблюдения стандартов чистоты кода Pinia (геттеры должны быть чистыми функциями вычисления состояния).

### 8. Определение назначения `useBlockStore('main')` в `uiStore`
* **Статус:** ⏳ В очереди
* **Описание:** Ранее в `uiStore` присутствовала зависимость от `useBlockStore('main')`. Сейчас она закомментирована/удалена. Необходимо провести аудит кода и полностью удалить любые остаточные упоминания, если они больше не требуются.

### 9. Получение справочника фильтров из API в портфолио
* **Статус:** ⏳ В очереди
* **Описание:** Сейчас список фильтров (`workclass`) захардкожен в компоненте `portfolio/index.vue`. Необходимо переписать логику так, чтобы справочник фильтров динамически запрашивался из эндпоинта категорий API.

### 10. Синхронизация i18n ↔ scope
* **Статус:** ⏳ В очереди
* **Описание:** Обеспечить бесшовную синхронизацию состояния плагина `vue-i18n` с изменением параметра `scope` в `uiStore` (и наоборот) в рамках отдельной выделенной итерации рефакторинга.

### 11. Исправление Vue Router Warning: `/:pathMatch` mismatch
* **Статус:** ⏳ В очереди
* **Описание:** Устранить предупреждение в консоли от Vue Router касательно несовпадения параметров для catch-all маршрута (NotFound). Проверить регулярное выражение в `src/router/index.js`.
