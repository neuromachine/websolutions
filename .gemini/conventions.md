# Конвенции и Стандарты Кодирования

В данном документе закреплены правила организации кода, именования сущностей, разделения обязанностей между компонентами и общие соглашения по стилю.

---

## 1. Терминология: `scope` против `locale`

Исторически в проекте использовались смешанные термины, однако для однозначности принято строгое разделение понятий:

| Термин | Назначение | Пример использования в коде |
|---|---|---|
| **`scope`** *(ранее section)* | URL-префикс текущего раздела или языковой версии. Используется для фильтрации запросов к API и роутинга. | `uiStore.scope`, `route.params.scope`, `normalizeLink(link, VALID_SCOPES)` |
| **`locale`** | Язык локализации интерфейса, используемый библиотекой `vue-i18n`. Синхронизируется автоматически со `scope`. | `i18n.locale`, `uiStore.currentLocale` |

*Все новые файлы, параметры, переменные и эндпоинты должны использовать исключительно слово `scope` для обозначения префиксов путей и разделов.*

## 2. Архитектура компонентов: Слои и Зоны ответственности

Для обеспечения расширяемости и простоты тестирования все новые страницы и блоки должны строго придерживаться многоуровневого разделения ролей:

### 2.1 Схема разделения компонентов
```
View.vue          — только компоновка (Header, Footer, PageTitle, блоки)
  │                 [НЕ содержит бизнес-логики, НЕ импортирует stores/composables]
  │
  └─ index.vue    — Оркестратор Блока
                    [Владеет инстансом store, вызывает fetch, единственный]
                    [кто использует usePageOrchestrator(..., isPageOwner)]
       │
       └─ list.vue — Презентационный Оркестратор
                     [Принимает очищенные данные через props, управляет]
                     [внутренней логикой блока: фильтры, сортировки, пагинация]
            │
            └─ item.vue — Чистый Презентационный Компонент
                          [Только отображение, полностью зависит от props]
```

### 2.2 Правила для ИИ и разработчиков
* **Файлы `View.vue` (например, `src/views/Home.vue`):** Только импортируют крупные секции и собирают страницу. Никакой логики выборки данных (`fetch`), никаких хранилищ.
* **Файлы `index.vue`:** Это мозг блока. Сюда импортируется `usePageOrchestrator`. Именно здесь генерируются или запрашиваются данные. Они передаются в дочерние компоненты в виде реактивных пропсов.
* **Дочерние компоненты (`list.vue`, `item.vue`, `card.vue`):** Им запрещено напрямую импортировать `useBlockStore`, `useUiStore` или осуществлять сетевые запросы. Все необходимые данные должны приходить через `defineProps`. Если дочернему компоненту нужно сообщить о действии пользователя, он использует `defineEmits`.

## 3. Общие правила разработки

### 3.1 Vue и Composition API
* Всегда используйте синтаксис `<script setup>` на TypeScript или чистом JavaScript (в зависимости от файла).
* По возможности типизируйте пропсы и эмиттируемые события.
* Избегайте использования `this`.

### 3.2 Маршрутизация и Компонент `AppLink`
* Любые переходы внутри приложения должны быть обёрнуты в компонент `<AppLink>`.
* `<AppLink>` автоматически добавляет активный префикс `scope` к переданному пути.
* **Пример строки:** `<AppLink to="/portfolio">Портфолио</AppLink>` сгенерирует `/en/portfolio`, если активный `scope` равен `'en'`.
* **Поддержка объектов:** Ведётся работа по адаптации `<AppLink>` под именованные маршруты `{ name: 'route_name', params: { ... } }`. Всегда тестируйте передачу объектов путей.

### 3.3 Работа со стилями (CSS)
* Проект плавно переходит на TailwindCSS (интеграция `@tailwindcss/vite` версии 4).
* Существующие стили шаблона находятся в `src/assets/styles/`. Не изменяйте глобальные файлы шаблона без явной необходимости.
* Для новых компонентов предпочтительно использовать утилитарные классы TailwindCSS или scoped CSS во Vue-файлах (`<style scoped>`). Avoid inline styles.
