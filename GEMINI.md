# Инструкции проекта и ИИ-Контекст (GEMINI.md)

Добро пожаловать в проект **websolutions**! Этот файл является главным входным узлом для ИИ-ассистентов и разработчиков. Он определяет глобальные правила работы, структуру контекста и указывает на модульные файлы в директории `.gemini/` для глубокого погружения.

---

## 🚀 Быстрый запуск и команды

- **Разработка:** `npm run dev` (запуск Vite-сервера локально)
- **Сборка:** `npm run build` (подготовка production-билда)
- **Тестирование:**
  - `npm run test` (запуск Vitest в интерактивном режиме)
  - `npm run test:run` (однократный запуск всех тестов — рекомендуется для CI/ИИ)
  - `npm run test:coverage` (расчёт покрытия тестами)

## ⚠️ Критические золотые правила для ИИ (AI Golden Rules)

При работе с кодовой базой **websolutions** строго соблюдайте следующие принципы:

1. **Никакого прямого импорта Stores в презентационных компонентах:** Презентационные компоненты (дочерние блоки) получают данные исключительно через `defineProps`. Прямой доступ к хранилищам разрешён только в оркестраторах уровня `index.vue`.
2. **Используйте фабрику `useBlockStore(id)` правильно:** Помните, что `blockStore` не является глобальным синглтоном. Это фабрика. Каждый блок имеет независимый инстанс, определяемый по ID. При получении стора всегда передавайте нужный ID: `useBlockStore(blockId)`.
3. **Сохраняйте чистоту `beforeEach`:** Запрещено совершать асинхронные API-запросы внутри хука `beforeEach` роутера. Хук должен заниматься только синхронной синхронизацией состояния интерфейса (например, обновлением `scope` в `uiStore`).
4. **Используйте `AppLink` вместо `RouterLink`:** Все ссылки внутри приложения должны использовать компонент `<AppLink>`, который автоматически подставляет текущий `scope` в URL.
5. **Не ломайте автоопределение `isPageOwner`:** Только один оркестратор на странице (владелец страницы) должен изменять глобальный контекст страницы (`buildPageVars`). Это определяется автоматически внутри `usePageOrchestrator`. Убедитесь, что параметры вызова оркестратора соответствуют логике роутинга.
6. **Добавление тестов:** Любая новая функциональность или исправление критических багов должны сопровождаться модульными тестами в папке `tests/` с использованием `vitest`.
